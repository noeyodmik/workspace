정연홍

사원에 관련된 정보를 담아두는 곳을 인포타입이라고 하면 해당 인포타입은 IMG를 통해서 설정 및 기준데이터를 관리할 수 있다.

Chapter 8. 급여 관련 추가 인포타입
급여 관리 IMG

<그림> 8.1 급여 관리 IMG

Chapter 6, 7을 통해서 인사 관리 IMG에 따라, 급여에서 사용되는 인포타입 설정에 대해서 알아보았다. 인사 관리 파트는 회사마다 사용하는 임금 유형에 대한 구분 작업이었다고 하면, 실제 해당 임금 유형별로 급여 계산 시 계산 방법에 대해 설정하는 곳이 급여 관리 IMG라고 할 수 있다. 물론 앞으로 급여 관리 부분에서도 인포타입 화면과 관련되는 곳이 있지만, 전체적인 설정은 급여 계산에 관련되어 있다. 급여 계산 이후 회계로 전표를 처리하는 부분도 있다.

▶ Overview
IMG의 구분상으로 나누어져 있지만, 이전 단계의 인포타입에 대한 설정은 같은 맥락을 가지고 있다. 필수 항목으로 사용하는 항목은 아니지만, 부가적으로 사용되는 항목 중에서도 급여와 연계되는 인포타입의 설정을 하게 된다. 

개인 데이터, 포상, 징계, 병역, 사회보험, 세금과 관련하여 인포타입에 추가적인 설정을 배우게 된다. 특히 세금부분에 언급될 이전 근무지에 대한 내역은 연말정산에서 사원의 이전 근무지 사업자등록번호를 입력하는 기준 데이터를 관리하는 화면이 있다. 방식에 따라 담당자가 해당 화면에서 관련된 이전 근무지를 등록하거나, 사원이 ESS를 통해서 직접 입력할 수 있을 것이다. 

인포타입에 관련된 설정은 항상 설정 후 해당 인포타입에서 확인 절차를 가져가는 것이 가장 좋다. 해당 변경 사항을 매번 확인하고 진행해야 누락이나 오류를 제때 확인할 수 있다. 



1. 인사 관리
▶ 목적
급여:한국 이하의 메뉴이기 때문에 인사 관리(급여 데이터)에서 설정하지 못한 인포타입에 대한 처리 및 사회보험, 세금 관련 설정을 하게 된다. 

▶ IMG Path
급여 관리 -> 급여:한국 -> 인사 관리

1.1 가족/친척 관련 추가 데이타 유지보수
▶ IMG 화면

<그림> 8.2 가족/친척 관련 추가 데이타 유지보수

▶ IMG Path
급여 관리 -> 급여:한국 -> 인사 관리 -> 가족/친척 관련 추가 데이타 유지보수

가족 정보에 대해서는 Infotype 0021(가족구성원/피부양자)에서 관리가 된다. 가족 관련 인포타입 설정은 인사 관리 -> 인사 관리 -> 개인 데이터 -> 가족에서 관리가 된다. 가족 정보에서는 인포타입의 하위 유형으로 크게 구분하는 '가능한 가족구성원 정의'가 있고, 해당 하위 유형별로 어떤 관계의 가족인지의 구체적인 정보를 담는 '관계'의 경우를 가족/친척 관련 추가 데이타 유지보수에서 설정하고 있다. 인사 관리 파트에서도 '가족/관계자의 추가 데이타 유지보수'가 있으나 국가 그룹핑 설정이 일본 버전으로 되어 있어서, 급여 관리 파트에서 설정하는 것이다. 관련 뷰 테이블은 'V_T7KRC6'이다. 인사 관리의 일본 버전은 뷰 테이블 'V_T5J85'을 사용하고 있다. 실제 내부 테이블은 같지만, 국가 그룹핑 구분되고 있다. 


<그림> 8.3 추가 데이타 유지보수 관련 뷰 테이블 일본 버전(V_T5J85)


<그림> 8.4 추가 데이타 유지보수 관련 뷰 테이블 한국 버전(V_T7KRC6)

MOLGA, EIGSH 값이 국가에 따라서 다른 값으로 처리되는 것을 알 수 있다. 

　　　<그림> 8.5 Infotype 0021(가족구성원/피부양자)

<그림> 8.5에서 관계에 입력할 항목들을 정의하여 설정하면 된다. 정보성 필드로 사용자가 가족 관련 보고서 작성 시에 활용할 수 있다. 간단하게 가족정보에서 중요한 부분을 짚고 넘어가자면, 부양가족(기타) 항목 중 부양가족 유형 부분이 가장 중요하다. 그림에서처럼 공백으로 처리한 경우에는 추후 연말정산 지급 매체 생성 시에 홈택스 신고 시에 매체 오류가 발생하게 된다. 연말정산 책자에 근거하여 유형을 반드시 입력해야 한다. 


<그림> 8.6 가족/친척 관련 추가 데이타 유지보수 상세 내역
신규 엔트리를 이용하여 숙련도(가족 관계) 코드를 입력하고 내역을 입력하며 된다. 코드에는 특별한 의미가 없으므로 사용자가 범위로 구분하여 가족의 관계 유형을 정리하면 된다.

<그림> 8.20 교육기관 정의

▶ IMG Path
급여 관리 -> 급여:한국 -> 인사 관리 -> 추가 개인 데이터 -> 실업급여에 대한 데이터 매체 교환 -> 학력 -> 교육기관 정의

고용보험에 가입하거나 퇴사로 인한 상실이 발생하게 되면 사업주는 해당 사원의 고용보험 가입/상실에 관련하여 신고해야 한다. 신고 시에 해당 사원의 학력 정보가 기재되어야 하고, 학력에 관련해서는 1. 초졸 이하, 2. 중졸, 3. 고졸, 4. 전문대졸, 5. 대졸, 6. 석사과정 졸업, 7. 박사과정 졸업 이상과 같이 코드를 사용하게 된다. 교육기관 정의는 고용보험사에서 사용되는 기준 코드 값을 관리한다. Standard의 내역 그대로 사용해야 한다. 관련 뷰 테이블은 V_T7KRE1이다.

직무 유형의 경우는 두 가지 용도로 사용될 수 있다. 첫 번째는 이전 단계에서 언급하였던 취득/상실 신고서 제출 시에 해당 사원의 직업 구분으로 처리된다. 해당 내용은 고용보험 취득/상실 신고서를 참조하게 되면, 별지로 '한국고용직업분류 중 소분류(119개) 직종 현황'이라는 표가 있다. 해당 내역은 Standard에서 이미 제공을 하고 있다. 이후 변경이 되면, SAP Korea를 통해서 Support Package를 적용받아야 할 것이다.

　　　<그림> 8.28 Infotype 0557(보훈/장애) 생성 화면

직무 유형이 '011'이 아닌 '0' 값이 넘어온다. 이 부분은 내부 로직에 문제가 있어서 정상적으로 처리되지 않는 것이다. OSS를 통해서 SAP로부터 수정을 받아야 하는 부분이다. 

FORM GET_DEFAULT.
  DATA:  SUBRC LIKE SY-SUBRC,
         JOBTY TYPE C,  -> JOBTY(3) TYPE C, 변경되어야 함
         RECUT TYPE C,
         NOTIF TYPE C,
         SUBST TYPE C,
         CHJOB TYPE C.

  MOVE-CORRESPONDING PSYST TO PME04.
* MOVE T001P-MOLGA TO PME04-MOLGA.

* Get default value of job type.
  PERFORM RE549D USING '41JOB' ' ' JOBTY SUBRC.
  IF SUBRC EQ 0 AND JOBTY NE SPACE.
     MOVE JOBTY TO P0557-JOBTY.
  ENDIF.　　　<소스> 8.2 Perform GET_DEFAULT 내용

Feature 41JOB를 통해서 리턴 받는 값이 JOBTY이다. JOBTY의 선언을 Char 1자리로 선언을 하여 리턴되는 값이 1자리로 고정이 되어 버려, 41JOB에 '011'이라고 기본값을 지정하였지만, 정상적으로 리턴되지 않는 것이다. 기본값이 반영이 안 되지만, Infotype 에서 직접 입력하는 것은 문제가 없다.

섹션 코드의 경우는 IMG상에서 재무회계(신규) -> 재무회계 전역세팅(신규) -> 원천세 -> 확장된 원천세 -> 기본세팅 -> 한국 -> 섹션 코드정의에서 설정한다. 섹션 코드는 사업장, 세무서, 지방세무서로 구분된다. 세금에 관련하여 취합하고, 납부하는 단위에 대한 정보를 담고 있는 것이 섹션 코드이다. 사업장은 재무회계(신규) -> 재무회계 전역세팅(신규) -> 부가가치세 -> 기본세팅 -> 한국 -> 사업장 -> 사업장 정의 에서 설정한다. 사업장의 경우는 세무서 정보를 가지고 있고, 해당 사업장별 대표, 사업장등록번호와 같은 정보를 담고 있다. 부가가치세와 같은 세금을 취합하는 단위로 설정된다. 원천징수영수증과 같은 출력물을 출력 시 해당 사원이 소속된 인사하위영역에 맞물려 있는 섹션 코드와 사업장의 정보를 이용하여 관련 대표자 정보를 출력하게 된다. 


<그림> 8.57 사업장 및 섹션 코드 지정 상세 내역

인사영역/인사하위영역은 이미 구성이 되어 있고, FI에서 설정된 섹션 코드와 사업장코드를 해당 인사하위영역에 맞게 입력을 한다. Enterprise Structure의 경우는 무작위로 구성하는 것이 아니라, SAP내의 설정에 따른 구분이나, 법적인 사항에 따라 구분이 된다. 특히 인사하위영역을 분류하는 항목 중에는 세금 납부 단위가 있다.

사회보험는 Infotype 0543(사회보험)과 Infotype 0544(사회보험료)로 구분이 된다. 이전 단계는 Infotype 0543(사회보험)의 수취자격에 대해 설정하였고 표준보상 부분은 Infotype 0544(사회보험료)의 보험료 설정에 관한 설정이다. 양쪽 인포타입에 각각 입력되면 급여 계산을 통해서 사회보험료가 계산된다. 사회보험료 계산은 function KRSIP를 통해서 처리된다. 

건강보험의 경우는 2007년 이후로 보험료 산출방식이 변경되었다. 2007년 이전의 경우는 표준보수월액 등급구간표에 근거하여 표준보수월액에 보험료율을 곱하여 산출한다. 2007년 이후는 해당 사원의 전년도 기준으로 공단에서 제공하는 평균 보수월액에 보험료율을 곱하여 산출한다. Infotype 0544(사회보험료) 화면의 월간보상금액 필드에 입력된 금액에 보험료율을 곱하는 방식이다. 사실상 표준보상테이블은 건강보험의 경우에는 2007년 이후 계산 방법에서는 사용되지 않는다. 단, 최저보상금액과 최대보상금액은 T511P에서 각각 MINMC, MAXMC 변수명으로 관리된다. 


<그림> 8.75 Infotype 0544(사회보험료) 건강보험 입력 화면

화면에서 월간보상금액에 특정 금액을 입력하면, 해당 보험료율을 곱하여 보험료를 산출하여 화면에 보여준다.
