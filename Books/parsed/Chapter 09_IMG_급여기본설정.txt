정연홍

급여 형태는 연봉제, 호봉제로 크게 구분할 수 있으며, 급여기간, 지급일에 따라 다양한 형태로 설정할 수 있다.

Chapter 9. 급여 기본 설정

1. 급여 조직
▶ 목적
급여를 계산하기 위한, 기본 항목들에 대해 설정한다. 급여 계산 영역, 급여 사유, 누적 처리, 임금 유형의 속성 정의와 같은 급여 계산을 기본 항목들에 대한 설정이다. 

▶ IMG Path
급여관리 -> 급여:한국 -> 기본 세팅

1.1 기간 매개 변수 정의

▶ IMG 화면

<그림> 9.1 기간 매개 변수 정의

▶ IMG Path
급여관리 -> 급여:한국 -> 기본세팅 -> 급여 조직 -> 기간 매개 변수 정의

급여 계산 기간 테이블을 구성할 때, 회사 내의 급여 지급 기간에 맞춰서 기간 매개 변수를 생성해야 한다. 가령, 월별로 지급, 격주로 지급하는 경우가 있는 경우 기간 매개 변수를 두 개를 생성해야 한다. 그리고 급여 시작일 1일이 아닌 경우에도 해당 시작일에 맞게 처리해야 한다. 


<그림> 9.2 기간 매개 변수 내역

기간 매개 변수에 대해서 standard에서 제공해주는 내역이다. 지급기간이 월간이고, 시작일이 1일이라면, 기간 매개 변수 01을 사용하면 된다. 그렇지 않은 경우는 사용자가 추가적인 기간 매개 변수를 만들어야 한다. 
1.2 일자수정자 정의

▶ IMG 화면


<그림> 9.3 일자수정자 정의

▶ IMG Path
급여관리 -> 급여:한국 -> 기본세팅 -> 급여 조직 -> 일자수정자 정의

회사 내에 같은 급여 지급 기간이지만, 지급일이 다른 경우에 기간 매개 변수를 공유하면서 일자수정자를 통해서 구분할 경우에 사용한다. 


<그림> 9.4 일자수정자 내역

Standard에서 기본으로 제공하는 내역이다. 사용자가 필요한 경우에 임의적인 코드로 구분하여 이후 급여계산 기간 생성 시에 사용할 수 있다.


1.3 급여계산 영역 점검

▶ IMG 화면


<그림> 9.5 급여계산 영역 점검

▶ IMG Path
급여관리 -> 급여:한국 -> 기본세팅 -> 급여 조직 -> 급여계산 영역 점검

급여계산 영역을 생성하는 부분은 인사관리 -> 인사관리 -> 조직 데이터 -> 조직지정 -> 급여계산 영역 생성(두 번째) 해당 부분에서 생성할 수 있다. 위 메뉴에서도 생성할 수 있다. 위치상으로 미리 생성한 경우에 점검에 의미를 부여해서 메뉴명이 점검일 것이다. 급여계산 영역은 급여를 계산하기 위한 그룹핑 및 계산기간, 급여 처리에 대한 제어까지 관련하고 있다. 특히 이전 단계에서 생성한 기간 매개 변수, 일자수정자를 이용하여 급여계산 기간을 설정해주는 역할을 한다. 급여계산 영역은 급여계산 영역 및 해당 제어레코드를 생성하는 두 가지의 액티비티로 구성이 되어 있다.


<그림> 9.6 급여계산 영역 생성 화면

급여계산 영역은 infotype 0001(조직지정)에 해당 사원의 영역을 지정하고 급여 계산 시에 해당 영역별로 계산 처리가 가능하다. 기간 매개 변수는 계산영역의 급여기간일자를 생성할 경우에 참조하여 처리되며, 이후에도 급여기간을 조회하는 경우에도 참조되어 활용된다. 급여계산실행은 체크가 되어 있지 않은 경우에는 급여 계산이 되지 않는다. 만약 회사 내에 급여는 실행하지 않지만, 관리를 해야 하는 경우에 체크를 하지 않은 급여계산 영역으로 지정하면 급여처리가 되지 않는다. 


<그림> 9.7 급여관리 레코드 관리 화면(T-CODE : PA03)

급여계산 영역에 따라서, 급여 계산을 제어하는 레코드를 생성해야 한다. 생성된 레코드에 따라서 급여 계산이 가능하고, 불가능하거나 하다. 그에 따라 마스터 데이터에 대한 lock 처리가 같이 연동이 된다. 운영 서버에서는 급여관리레코드에 의해서 반드시 처리가 되어야 한다. 


<그림> 9.8 급여관리 레코드 내역

급여계산 상태는 이전 장에서 설명한 것과 같이 급여 릴리즈 -> 수정 릴리즈 -> 급여종료 상태로 이어진다. 최초 재계산 기간에 따라 마스터 데이터에 대한 변경이나 소급이 제어된다. 

1.4 급여계산 기간 생성

▶ IMG 화면

<그림> 9.9 급여계산 기간 생성

▶ IMG Path
급여관리 -> 급여:한국 -> 기본세팅 -> 급여 조직 -> 급여계산 기간 생성

급여계산 영역에 맞는 급여계산 기간을 생성하여, 테이블로 관리하고, 급여 계산 시에 활용하게 된다. 급여지급 시작일, 종료일(기간) 그리고 급여지급일로 급여계산 기간이 생성된다. 급여계산 기간을 생성하는 프로그램은 RPUCTP00이고, 해당 매개변수를 입력 후 생성하여 내역을 확인할 수 있다. 확인을 통해서 정상적이라는 판단이면, 실제 테이블에 변경처리를 할 수 있는 방식을 되어 있다. 예를 들어, 지급 기간은 월간 단위로 처리하고, 급여 지급일은 25일, 시작일은 2008.01.01부터인 급여계산 기간을 생성하고자 할 경우에는 다음과 같이 입력하면 된다. 

<그림> 9.10 매개변수 입력 내용
급여일 룰의 경우는 1. 기간시작일에 일수 추가, 2. 기간종료일에서 일수 공제, 3. 기간종료일에 일수 추가, 4. 월별전용-지급일로 사용된 일수로 이루어져 있고, 일수 필드에 해당 값을 입력하면, 룰에 의해 지급일이 결정된다. 그림5.290 에서는 월별전용일로 25를 사용하겠다는 의미가 된다. 만약 급여 지급일이 다음 달 10일인 경우는 기간종료일에 일수 추가와 같은 방법을 사용해도 가능할 것이다. 


<그림> 9.11 급여계산 기간 생성화면

위의 매개변수 규칙에 따라 생성한 화면이다. 시작, 종료는 급여기간이고, 급여일이 급여지급일이다. 기간과 연도는 해당 급여기간으로 설정된 값이다. 설정에 따라 기간은 01/2008이더라도, 급여기간은 2008.02.01 ~ 2008.02.29가 될 수도 있다.

<그림> 9.21 Schema 속성 화면

▶ IMG Path
급여관리 -> 급여:한국 -> 기본세팅 -> 임금 유형 유지보수 환경 -> 처리 클래스 및 평가 클래스 -> 처리 클래스 및 해당 사양 유지보수

Schema를 분석할 때 처리 클래스에 대해서 언급을 했었다. 처리 클래스나 평가 클래스의 경우 급여 계산 시에 임금 유형별로 정해진 클래스 값으로 처리된다. 관련 처리 클래스의 유형 및 클래스별 입력 가능한 값에 대한 유지보수하는 IMG이다. 


　　　<그림> 9.25 처리 클래스 내역

Standard에서 제공하는 클래스 내역들이 나타나고, 해당 클래스별로 입력 가능한, 혹은 해당 값에 따라 급여 계산 시 처리되는 내역에 정보를 조회할 수 있다. 사용자가 회사 내의 급여 계산 규칙에 따라 사양을 추가하거나, 사용자가 임의의 클래스를 생성할 수 있다. 한국 급여가 모든 클래스를 사용하는 것이 아니므로, 적정한 번호 안의 범위에서 생성하고 관련된 Rule을 생성하여 Schema에서 사용할 수 있다. 


<그림> 9.26 처리 클래스 10의 사양 내역


<그림> 9.27 처리 클래스 10을 사용한 Rule XVAL 내역

VWTCL 10은 해당 임금 유형의 처리 클래스 10에 설정된 값 내용을 조회하여 관련 규칙에 따라 처리된다고 이야기했었다. 처리 클래스 사양은 급여 계산 시에 처리될 수 있는 방법의 종류를 의미하고, 실제 방법은 Rule상에서 Standard 혹은 사용자가 생성해야 한다. 물론 대부분의 처리 클래스와 관련된 Rule은 standard에서 제공하고 있다.


2.2 평가 클래스 및 해당 사양 유지보수

▶ IMG 화면

<그림> 9.28 평가 클래스 및 해당 사양 유지보수

▶ IMG Path
급여관리 -> 급여:한국 -> 기본세팅 -> 임금 유형 유지보수 환경 -> 처리 클래스 및 평가 클래스 -> 평가 클래스 및 해당 사양 유지보수

임금 유형에 관련된 속성 중 테이블 T512W에는 처리 클래스, 누적 클래스, 평가 클래스가 존재한다. 그 중 평가 클래스는 급여 서식에서 임금 유형별로 출력하고자 하는 경우에 사용된다. 총 20개의 평가 클래스가 존재하고, Standard에서는 1 ~ 17번까지 사용하기 때문에 사용자가 임의의 평가 클래스를 사용하고자 하는 경우는 18 ~ 20번까지만을 사용할 수 있다. 한국 급여의 경우는 1,2,3을 사용하고 있다. 그중에서도 2번을 Standard에서 제공하는 급여명세서에서 그룹핑 값으로 사용하고 있다. 


2.3 임금 유형 그룹에 대한 지정 점검

▶ IMG 화면


<그림> 9.29 임금 유형 그룹에 대한 지정 점검
　　　
▶ IMG Path
급여관리 -> 급여:한국 -> 기본세팅 -> 임금 유형 유지보수 환경 -> 논리 뷰 -> 임금 유형 그룹에 대한 지정 점검

임금 유형을 생성할 때 생성한 위치에 따라서, 해당 그룹별로 생성된다. 그룹이라는 것은 인포타입별로 구성이 되거나, 혹은 인포타입이 아닌 별도의 유사한 속성에 의한 그룹핑일 수 있다. 이 경우에 위 IMG를 통해서 재확인 혹은 그룹을 변경할 수 있는 설정이다. 


<그림> 9.30 임금 유형 그룹 편집 화면(임금 유형 그룹 0008 기본급)

<조회> 버튼을 클릭하면 해당 그룹의 임금 유형을 확인할 수 있고, <변경> 버튼을 클릭하여 다른 그룹의 임금 유형을 추가하거나 해당 그룹의 임금 유형을 제외할 수 있다.

임금 유형은 많은 속성을 가지고 급여 계산에서 활용된다. 처리 클래스, 누적 클래스, 평가 클래스와 같은 항목들에 해당 값을 설정할 수 있는 부분이 논리 뷰 점검이다.
