정연홍

급여 계산 기간과 지급 기간이 다른 경우 다시 말해 전월 데이터를 기준으로 당월에 지급하는 경우 이연지급을 통해서 처리할 수 있다. 

Chapter 10. 급여와 연계되는 근태 설정

▶ Overview
급여에는 많은 정보가 집중되어 하나의 결과인 급여항목들이 발생이 된다. 이런 측면에서 가장 많은 부분을 찾지 하는 정보 중의 하나는 근태이다. 이번 장에서는 특히 이연지급에 대해서 생각해봐야 할 것이다. 

그 외 항목들은 사실상 근태 설정에서 다루어야 할 것들이고, 혹은 Standard가 제공해주는 그대로 변형 없이 사용하는 항목들이 많다. 다만, 언급하는 이유는 이런 것들이 있고, 해당 항목들의 역할이 이러한 것들이구나 라는 것은 한 번 정도 생각해볼 만한 것들이기 때문에 언급하였다. 다소 생소하고, 쉽게 이해되지 않는 부분이지만, 이연지급만 이해한다면 충분히 이번 장을 소화했다고 본다. 

이연지급은 급여 기간과 근태 수당 기간이 상이한 경우 처리하는 방식으로 처리 메커니즘은 어렵지 않은 그로 인해 파생되는 평균임금 산입 시점에 따라 많은 부분이 복잡해지기 시작한다. 지급은 이연으로 하고, 평균임금은 발생주의로 하면, 그 산식의 복잡함은 쉽지 않거니와, 업무적으로도 미완결되거나 혹은 아직 마감되지 않은 정보를 평균임금에 산입하기 위한 노력이 매우 많이 소요될 것이다. 이연지급이라는 단순한 항목 조차에서도 많은 파생부분이 생기는 것처럼 하나를 이해하는 것도 중요하지만, 그로 인한 영향에 대해서 고민하고, 설계하고, 설정하는 습관도 필요하다. 
1. 시간 데이터 일일 처리
▶ 목적
시간 평가를 통해서 시간임금 유형을 생성할 때 사용되는 기준에 대해 설정할 수 있다.

▶ IMG Path
급여 관리 -> 급여:한국 -> 시간 데이터 일일 처리

1.1 시간 유형 정의
▶ IMG 화면

<그림> 10.1 시간 유형 정의

▶ IMG Path
급여 관리 -> 급여:한국 -> 시간 데이터 일일 처리 -> 시간 유형

시간 데이터 일일 처리 부분의 IMG는 시간 평가 부분에서 사용되고, IMG 메뉴 근태 관리 아래에 있다. 다른 IMG 설정에 비해서는 Standard 내역을 그대로 사용하는 편이다. 근태 관리 IMG의 근태 관리 -> 시간 평가 -> 시간 계산 세팅 -> 시간유형 정의에 같은 화면이 있다. 

시간 평가를 통해서 임시 테이블인 TES에 생성되어 시간 평가가 마무리되면 TES의 내용은 ZES와 SALDO로 저장이 된다. ZES는 일일별로 해당 시간 유형 내역이 저장되고, 해당 유형의 속성에 따라 SALDO에 기간단위로 누적되게 된다. 


<그림> 10.2 시간 유형 내역

PSGpg는 인사하위영역 그룹핑 값으로, 시간 관리 -> 시간 평가 -> 시간 계산 세팅 -> 시간기록용 인사하위영역 그룹핑 설정에서 설정한 값으로 사용한다. Standard에서 제공해주는 값은 '01'로 설정된 그룹핑 값으로 위 인사하위영역 그룹핑 값으로 사용한다.


<그림> 10.3 시간 유형 상세 내역

일일 밸런스로의 저장은 ZES로, 기간 밸런스로의 누적은 SALDO에 저장하게 된다. 


1.2 시간 페어에 시간 식별자 지정
▶ IMG 화면

<그림> 10.4 시간 페어에 시간 식별자 지정

시간 평가를 이용하는 이유 중 하나는 시간임금 유형을 생성하는 것이다. 시간관련 인포타입 내역을 이용하여 ZL을 생성하게 된다. 해당 내역은 TZP, TIP에 생성되어 해당 시간 내역이 어떤 타입인지 결정해주는 역할을 시간 페어에 시간 식별자에서 제공하게 된다. 하루는 근무시간, 휴식시간, 초과근무시간과 같이 구분하여 사용할 수 있다. 시간 식별자가 해당 유형에 따른 처리를 해주게 된다. 구분된 시간유형은 다시 ZL에서 생성될 수 있게 된다.

2. 휴무
▶ 목적
급여 계산 시 휴무에 따라서 지급 금액에 대한 가감이 발생할 수 있다. 이런 경우에 휴무에 따라 다른 규칙을 적용하고자 하면 IMG 휴무 이하의 메뉴를 활용하여 처리할 수 있다. 

▶ IMG Path
급여 관리 -> 급여:한국 -> 휴무

2.4 일일규칙 정의

<그림> 10.30 일일규칙 상세 내역

2.5 휴무 평가의 계산 클래스 생성
▶ IMG 화면

<그림> 10.31 휴무 평가의 계산 클래스 생성

▶ IMG Path
급여 관리 -> 급여:한국 -> 휴무 -> 휴무 평가 -> 휴무 평가의 계산 클래스 생성

휴무 평가에는 카운팅 클래스 방식, as if 원칙 방식, 상수/평균별 방식, 휴무 평가규칙 방식으로 세분화할 수 있다. 휴무 평가의 계산 클래스 생성에서는 전문가 모드를 통해서 해당 방식을 관리할 수 있다. 그중에서 카운팅 클래스 방식으로 휴무 평가를 생성할 수 있다. 휴무에 따라서, 급여 지급에 대해 처리하며 지급/미지급의 경우 백분율로 처리한다. 


<그림> 10.32 휴무 평가의 계산 클래스 상세 내역

백분율에 따라서 미지급 처리된다. 유급에 체크하면 결근이더라도 지급 처리된다. 이전 단계에서 생성했던 요일규칙을 적용하면, 조건에 따라서, 미지급이 안 될 수도 있다. 해당 백분율은 Schema XAL0에서 감산임금 유형을 생성하는 데 사용되고 해당 비율만큼 일할 처리가 될 것이다. 휴무 평가는 Schema KRT0의 Function PAB를 통해서 처리되며 해당 무급 내역은 테이블 CABC에 저장된다. 


<그림> 10.33 Function PAB 로그 내역

휴무 0203의 경우는 휴무 평가규칙은 VRule 값대로 04이고 CABC에 저장되는 것을 알 수 있다. CABC 값은 이후 Rule XPP1에서 감산인수에 영향을 주게 된다. RTE, AMT, NUM의 사용에서 T 타입인 경우에 Partial Period Parameter 항목에서 KAUxx, KAPxx(AAU, SAU, AAP, SAP)로 사용된다. 위 그림에서는 KAU01인 경우에 1의 값을 리턴한다. 


<그림> 10.34 카운팅 클래스 50%로 한 경우

카운팅 클래스를 100% -> 50%으로 줄이게 되면, Function PAB를 통해서 내부테이블인 CABC의 내역이 달라지는 것을 알 수 있다. 결근의 경우 무조건 100% 미지급이 아니라 특정일에 대해서는 일일규칙을 적용하여 백분율을 달리 적용할 수 있을 것이다. 


<그림> 10.35 CABC 내역(카운팅 클래스 유급 체크 시)

유급에 체크하면 ActivTyp이 U가 아닌 A로 변경된다. Rule XPP1에서 감산임금 유형 /801의 생성 규칙에서는 KAUxx에 대한 값을 제외하고 있어서 P로 변경된 CABC 내역은 영향을 주지 않게 된다. 특정 휴무의 경우에 무급휴무로 구분되지만, 급여에 영향을 주지 않게 하려면 유급에 체크하면 된다. 카운팅 클래스 방식을 사용해도 충분히 보편적인 회사 내의 무급처리는 가능하다.

2.7 상수/평균별 휴무 평가

<그림> 10.48 Rule XMOD 내역

Rule XMOD는 이전 단계에서도 언급됐었다. 이번에는 MODIF 2=01에 대해서 확인을 하면 된다. 상수평가인 경우 사원그룹핑에 따라 급여 관리 수정자를 지정하여 별도의 처리가 가능하다. MODIF 2=nn 테이블 T510J의 내역을 가져오는 그룹핑 값을 지정한다. 사원그룹핑 3의 경우는 01로 설정이 되었다. 


<그림> 10.49 임금 유형별 상수 평가 결정 내역

5.3 개인 관련 평가 기준 생성
▶ IMG 화면

<그림> 10.52 개인 관련 평가 기준 생성

급여 관리 -> 급여:한국 -> 시간임금 유형 평가 -> 평가 기준 -> 개인 관련 평가 기준 생성

시간임금 유형을 평가하기 위해서는 시급을 산정해야 한다. 시급을 산정하는 Schema에 대한 설명이 되는 IMG이다. 시급을 산정하기 위해서는 시급을 구성하는 임금 유형이 미리 지정되어 있어야 하고, 해당 임금 유형의 총금액을 시급을 산정하는 시간 수로 나눈 금액이 시급 단가가 된다. 

1) 시급 관련 임금 유형 총 금액 산정
standard에서 제공하는 Schema KRT0의 Rule KR10이 해당 역할을 하고 있다. Secondary Wage Type인 /001, /003을 구성하게 된다. /001은 이후 단계에서 시급으로 활용하고, /003은 일급으로 산출하기 위한 임금 유형으로 처리된다. /001은 처리 클래스 01에 관련된 사양에 따라 임금 유형의 금액 합산으로 생성되며, /003은 /001의 금액에 해당 계획근무규칙의 일일근무시간을 가산한 금액으로 합산된다. TABLE 508ANUM=BTGSTD 를 사용하여 테이블 T508A의 필드 TGSTD 내역으로 처리된다. 

2) 시간 수로 시급 단가 산정
Standard에서 제공하는 Schema KRT0의 Rule X013을 이용하여 Rule KR10에서 총 금액으로 합산된 금액을 해당 계획근무규칙의 월 근무시간 수로 나누어서 시급을 산정한다. 


<그림> 10.53 Rule X013(사원그룹핑 3)

처리 클래스 01의 사양 값이 5인 경우에만 처리된다. 평가임금 유형인 /001, /003의 경우는 5로 되어 있다. RTE=TSDIVP는 총 근무시간 수이다. 해당 시간 수는 Infotype 0008(기본급)의 근무시간/기간의 입력된 시간 수로 해당 금액을 나눈다. 

3) 시급 산정에 포함되는 임금 유형 지정

<그림> 10.54 처리 클래스 01에 대한 임금 유형 지정

시급 산정 여부는 처리 클래스 01에서 해당 사양을 지정하면 된다. /001, /003을 사용하는 경우는 사양 값 1로 지정하여 처리하면 된다. /002와 같은 임금 유형을 사용하고 자 하는 경우에는 다른 사양 값으로 조정한다. 혹 시급 단가 산정에 문제가 있는 경우는 임금 유형별로 처리 클래스 값을 재확인을 먼저 해보도록 하자.

IMG 메뉴에서 조회하는 경우에 임금 유형이 보이지 않을 수 있다. 임금 유형 논리 뷰를 이용하여 조회하게끔 되어 있어서, 해당 그룹에 임금 유형이 없는 경우에는 나타나지 않는다. 대신 SM30에서 뷰 테이블 V_512W_B로 조회하여, 전체 임금 유형을 조회하여 확인하도록 하자. 


<그림> 10.56 평가 기준 설정 내역

평가 기준에 따라서 이전 단계에서 설정했던 항목에 따라서 평가가 되고, 백분율은 평가임금 유형의 백분율로 가산되어 추가적인 금액이 계산될 수 있다. 평가 기준이 nn(예: 01, 02)와 같은 방식으로 입력하면, 평가임금 유형인 /001, /002, /003와 같은 임금 유형의 금액으로 평가를 받게 된다. K인 경우는 이전 단계에서 입력했던 테이블 T510J 내역으로 처리된다. 시간임금 유형의 경우는 일반적으로는 nn 방식을 이용하여 평가 처리된다. 야간수당 혹은 휴일수당과 같은 경우는 백분율을 이용하여 가산하거나, 해당 기준 금액으로 처리된다. 


5.5 평균값 계산 기준 생성
▶ IMG 화면

<그림> 10.57 평균값 계산 기준 생성

▶ IMG Path
급여 관리 -> 급여:한국 -> 시간임금 유형 평가 -> 평가 기준 -> 평균 -> 평균값 계산 기준 생성

평균의 경우는 퇴직금과 같은 평균임금을 생성하는 방식과는 다소 차이가 있다. 특정 사원이 결근이나, 부득이한 휴무로 인해 근무하지 않았을 때는 정상적인 급여를 지급하지 않고 기존에 지급받았던 금액을 기준으로 평균 금액을 제공하는 경우에 사용한다. 평균값 계산 기준 생성에서는 평균에 포함될 임금 유형을 선정하고, 특정 기간 매개변수 값을 지정하는 역할을 한다. 평균을 산출하는 방식은 임금 유형에 따라 구분할 수 있을 것이다. 임금 유형의 금액과 해당 기간 매개변수를 이용하여 평균을 내는 방식이나, 시간임금 유형과 같은 시간 수와 금액을 이용하여 평균을 산출하는 방식으로 나누어 볼 수 있다. 


<그림> 10.58 임금 유형의 서식 평균 기준 내역
Standard에서 제공하는 Secondary Wage Type 중 /2nn인 임금 유형이 평가 기준으로 사용되는 평균임금 유형이다. 평균기준에 따라서 포함되는 임금 유형을 지정하고, 비율, 횟수, 금액 중 어떤 부분에 대해서 누적하여 처리할 것인지, 정하고, 퍼센트를 이용하여 조정할 수 있다. 예를 들어 시간임금 유형에 대해서 횟수와 금액을 누적하려면 <그림> 10.58과같이 설정하면 된다. 


<그림> 10.59 부분기간 매개변수의 서식평균기준

평균기준에 부분기간 매개변수를 지정하고, 해당 값을 퍼센트로 조정한다. 이전 단계에서 임금 유형의 금액만을 누적한 방식이라면, 부분기간 매개변수를 이용하여 평균을 산정하기 위한 설정이다. '누적금액 / 부분기간 매개변수 = 평균'이라는 산식을 구성하게 된다. standard에는 TASOLL, TKSOLL, TSSOLL을 제공하고 있다. 더 많은 매개변수가 있으나, 프로그램상에서 주석으로 막혀 있다. 주석으로 인해서 부분기간매개변수를 이용하여 값을 산출하는 것은 부적절한 값이 나오게 된다. 추후 주석에 대한 부분은 OSS를 통해서 변경 요청이 필요할 것으로 생각된다. 

Include H99CAVERA -> PERFORM CUMULATE_AVERAGE_BASES -> FUNCTION HRPY_AVERA_CUMULATE_BASES에서 확인할 수 있다.

4) 누적규칙 생성

<그림> 10.64 누적규칙 내역

누적규칙에 연계된 평가 기준에 해당 규칙에 따라서 누적을 시키게 된다. 규칙 ZC01의 경우는 평균기준 /201에 누적을 시키는 방식이고, 금액 조정의 경우 조정규칙 ZA01에 따라서 이루어지는 것으로 설정된 내역이다. 팩토링의 경우는 누적 시 F, S, N의 유형에 따라서 팩토링이 이루어진다. 위 내역은 WPBP의 분할 사용 방식으로 일할 처리가 되는 설정이다. 화면에는 AMT 필드만 보이나, NUM, RTE 필드도 조정규칙을 정할 수 있게 되어 있다. 조정규칙을 사용하려면 해당 필드에 체크를 해야 하고 조정분에 대해서 +로 처리할 것인지, -로 처리할 것인지 조정할 수 있다. 

5) 최종규칙 생성 및 해당 규칙 내역

<그림> 10.65 최종규칙 내역


<그림> 10.66 Rule X018 내역

누적규칙과 조정규칙을 거쳐서 생성된 내역에 대해서 금액 필드 값을 수 필드 값으로 나눈 값을 비율필드에 저장하는 규칙을 제공한다. 평균 기준이 아닌 총액인 경우는 해당 규칙을 복사하여 필요에 맞는 방식으로 수정해야 한다. Rule X018의 경우는 IT, RT로 전송하는 규칙이 없으므로 추가하여 해당 평균기준을 관리할 수 있다. 

6) 비교규칙 생성

<그림> 10.67 비교규칙 생성

최종규칙을 통해서 생성된 내역을 다른 임금 유형의 값과 비교하여 대체하는 역할을 하는 규칙이다. 필드에서 수, 비율, 금액 필드를 선택하고 해당 비교에 따라 비교 임금으로 대체할 것인지를 선택하게 된다. Function HRPY_AVER_COMPARE_WGTP 을 이용하여 비교 임금 유형에 대해 처리하지만, 실제 내용에는 수와 금액에 대한 로직은 아직 없다. 해당 이유는 이전 단계에서 최종규칙 X018을 이용하여 금액/수 = 비율로 처리했기 때문에 비율 필드를 수정하는 로직만 있을 뿐이다. 

7) 평균 계산규칙 생성


<그림> 10.68 평균 계산규칙 내역

이전 단계에서 개별 규칙을 만들어왔다. 평균 계산규칙은 개별규칙을 하나의 규칙으로 묶는 역할을 하게 된다. 평균 임금규칙 명은 /2nn으로 생성한다. 내부 로직에서 규칙 이름을 임금 유형으로 사용하기 때문에 임금 유형 아닌 경우에는 정상적으로 처리되지 않는다.

<그림> 10.70 평가 기준 내역

<그림> 10.70에서 평가 기준 /001의 경우는 12,391의 단가로 생성된 것을 확인할 수 있다. 이후 단계에서는 임금 유형 2001(연장수당)은 평가 기준에 따라서 150% 금액으로 처리되면 18,586원이 기준이 될 것이다. 


<그림> 10.71 임금 유형 2001(연장수당) 평가 기준 처리 내역

임금 유형 /201(평균기준) 내역이 확인되고, 해당 임금 유형의 기준은 82,861원이다. 임금 유형 2001(연장수당) 역시 평균기준을 통해서 재처리된 내역이 확인된다. 기준 평가 기준으로 처리된 내역은 무시되고, 평균기준으로 처리된 내역으로 금액이 산정된다.

6. 이연지급
▶ 목적
급여 지급 기간과 근태 관련 임금 유형 지급 기간이 상이한 경우가 있다. 이런 경우에 급여로 시간임금 유형을 지급하는 경우에 사용하는 방식에 대한 설정이다.

▶ IMG Path
급여 관리 -> 급여:한국 -> 이연지급


6.1 이연지급일 설정
▶ IMG 화면

<그림> 10.77 이연지급일 설정

▶ IMG Path
급여 관리 -> 급여:한국 -> 이연지급 -> 이연지급일 설정

급여와 근태의 지급기간이 상이한 경우에는 해당 급여 계산 시에 근태에 대한 지급기간으로 별도로 조회하여 처리하여야 할 것이다. 이런 경우에 SAP에서는 이연지급이라는 방식을 통해서 처리한다. 예를 들어 급여 기간은 1일부터 말일이고, 근태 기간은 전월 16일부터 당월 15일이라고 하면, 이연지급은 급여 기간으로 근태 기간의 데이터를 조회하여, 계산을 한다. 당월 1일부터 15일까지는 당월에 지급을 하는 임금 유형으로 생성하고, 당월 16일부터 말일까지는 지급하지 않는 임금 유형으로 생성한다. 다음 달에는 전월 16일부터 전월 말일까지 미리 생성해둔 임금 유형을 전월 급여를 통해서 조회하고, 해당 임금 유형을 지급하는 임금 유형으로 변경하여 지급하는 방식이다. 


<그림> 10.78 이연지급일 설정 내역

이연지급일 설정은 상수 DEFER에 해당 값을 입력하는 것이다. 이렇게 설정된 값은 급여 계산 시에 Rule KRDF, KR80 그리고 급여 Function인 KRDPY를 통해서 처리된다. 위 그림처럼 16일로 설정하게 되면, 해당 월 16일부터 말일까지는 다음 달에 지급한다는 의미로 처리된다. 


6.2 이연지급 임금 유형 서식
▶ IMG 화면

<그림> 10.79 이연지급 임금 유형 서식

▶ IMG Path
급여 관리 -> 급여:한국 -> 이연지급 -> 이연지급 임금 유형 서식

이연지급은 조회된 임금 유형을 이연지급일 기준으로 지급할 임금 유형과 다음 달에 지급할 임금 유형으로 구분할 수 있다. 이연지급일을 기준으로 위 임금 유형으로 구분을 해주는 Rule은 KR80이다. Rule KR80에서 처리하기 위해서 처리 클래스를 설정하는데, 처리 클래스 61에 대해 설정하는 IMG이다.

처리 클래스 61 설정은 다음과 같다.
1: 임금 유형이 다음 달 급여에 지급됩니다. 
2: 임금 유형이 다음 달 급여에 평가되고, 지급됩니다.
3: 이연지급에 임금 유형을 차기 이월 합니다. 

해당 급여 기간으로 근태임금 유형을 조회하여 생성하는 기본 임금 유형의 경우는 처리 클래스 61의 1로 설정하고, 이연지급일 기준으로 다음 달에 지급할 임금 유형으로 구분된다. 다음 달에 지급할 임금 유형의 경우는 3으로 설정을 한다. 


<그림> 10.80 Rule KR80 내역(사원그룹핑 2)

Standard에서 제공하는 내역이다. 처리 클래스 61의 값을 조회하여, 해당 값이 1,2인 경우에 처리되는 내역을 살펴보면, 1인 경우는 RTE=& DFDT를 통해서 이연지급일을 조회하고, 만약 해당 임금 유형 지급일이 기준일보다 큰 경우는 라인 70번을 통해서 WGTYP+###1로 임금 유형 코드를 변경한다. 이런 식으로 임금 유형을 조절하기 때문에 이연지급을 하는 임금 유형의 경우는 연속된 번호로 이어져야 한다. 각각 다른 임금 유형으로 저장된다.
